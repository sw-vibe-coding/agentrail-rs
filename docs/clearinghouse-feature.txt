Markdown marker strategy
Use protected generated regions:

# CLAUDE.md

<!-- agentrail:global:start profile=rust-repo agent=claude version=2026-04-28 -->

<!-- agentrail:global:end -->

Repo-specific instructions go here.

Important rule categories
Your example should become a global corrective rule:

## Agentrail metadata discipline

When using agentrail saga/steps, changes to agentrail metadata are first-class project changes.

Before ending a task or reporting completion:

1. Run the relevant agentrail status/check command.
2. Confirm changed agentrail files are tracked.
3. Commit source changes and agentrail metadata together unless explicitly instructed otherwise.
4. Push or prepare the branch according to the repo workflow.
5. Mention the commit hash or unpushed branch state in the handoff.
That belongs in something like:

global/agentrail-process.md
incidents/2026-04-28-agentrail-metadata-not-committed.md
The incident file is useful because it explains why the rule exists.

agentrail launch workflow
A command like this makes sense:

agentrail launch claude
agentrail launch codex
agentrail launch opencode
What it should do:

1. Read .agentrail/instruction-profile.toml
2. Fetch or update the central instruction repo
3. Resolve global + profile + agent-specific instructions
4. Rewrite generated blocks in CLAUDE.md / AGENTS.md
5. Record instruction version in .agentrail/instruction-lock.toml
6. Optionally commit the instruction refresh
7. Start the requested agent
Example:

agentrail launch claude --update-instructions --commit
Could produce:

Updated CLAUDE.md global block:
  previous: 2026-04-22
  current:  2026-04-28

Committed:
  chore(agentrail): refresh shared agent instructions
Per-repo profile
Example:

# .agentrail/instruction-profile.toml

profile = "rust-repo"
agents = ["claude", "codex", "opencode"]

include = [
  "global/baseline.md",
  "global/git-hygiene.md",
  "global/agentrail-process.md",
  "global/testing.md",
  "agents/common.md",
]

[repo]
preserve_local_sections = true
require_instruction_lock = true
Then central profiles/rust-repo.toml can define the shared defaults.

Version tracking
Use a lock file:

# .agentrail/instruction-lock.toml

instruction_repo = "git@github.com:sw-cli-tools/agent-instructions.git"
revision = "a8f31c9"
profile = "rust-repo"
agent = "claude"
updated_at = "2026-04-28T08:45:00-07:00"

files = [
  "CLAUDE.md",
]
This gives you reproducibility. Later, if an agent misbehaves, you can ask:

Which version of the shared instructions did it have?

Commands I would add
Minimal useful set:

Then later:

agentrail instructions add-rule

Strong design choice
I would not make every repo manually vendor a full copy of the central instructions.

Better:

CLAUDE.md / AGENTS.md contains enough generated instruction text for the agent to read.
.agentrail/instruction-lock.toml records where it came from.
agentrail refreshes it from the central repo.
This avoids relying on the agent to follow links or inspect another repo.

Handling different agent formats
Have one canonical rule source, then render into agent-specific forms:

Canonical fragments:
  global/git-hygiene.md
  global/agentrail-process.md

Rendered outputs:
  CLAUDE.md
  AGENTS.md
  CODEX.md
  OPENCODE.md
This prevents drift.

The renderer can prepend small agent-specific wrappers, but the core rule text should stay identical.

Recommended MVP
Build this in stages:

Stage 1: Manual central repo
Create central markdown fragments and copy/paste as needed.

Stage 2: agentrail instructions apply
Regenerate marked blocks in CLAUDE.md and AGENTS.md.

Stage 3: Lock file + diff
Track central repo revision and show what changed.

Stage 4: agentrail launch
Make launching an agent automatically refresh instructions first.

Stage 5: Incident/rule workflow
Add a command that turns a mistake into a reusable rule:

agentrail instructions record-incident \
  --title "Agents forgot to commit agentrail metadata" \
  --rule global/agentrail-process.md
My preferred architecture
Central rule repo
       |
       v
agentrail instructions resolver
       |
       v
generated instruction block in CLAUDE.md / AGENTS.md
       |
       v
agent starts with fresh shared + local instructions
This gives you the clearing house you want without losing repo-specific knowledge.

Better model

Then compile them into the binary with Rust include_str!() / include_dir.

Cache probably not needed
For this use case, I would not use cache as the source of truth.

Use:

agentrail-rs repo committed/pushed
        ↓
sw-install reinstalls/rebuilds agentrail
        ↓
agentrail binary contains latest global instructions
        ↓
agentrail launch/apply rewrites generated blocks
That is simpler and safer.

What should be ephemeral?
~/.local/softwarewrighter/cache should only be for things like:

downloaded temp files
expanded templates
last-rendered previews
tool runtime scratch
Not canonical rules.

If needed, rename conceptually:

~/.local/softwarewrighter/tmp/agentrail/
or:

~/.local/softwarewrighter/state/agentrail/
But for embedded global instructions, even that may be unnecessary.

Recommended command behavior
agentrail instructions apply
agentrail launch claude
Should:

Read embedded global instruction fragments from the binary.

Read repo-local preserved blocks from CLAUDE.md / AGENTS.md.

Replace only marked generated sections.

Leave local sections untouched.

Warn if generated files changed and are not committed.

Compile-time embedding
Example Rust shape:

pub const GLOBAL_AGENTRAIL: &str =
    include_str!("../agent-instructions/global/agentrail-saga.md");

pub const GLOBAL_GIT_HYGIENE: &str =
    include_str!("../agent-instructions/global/git-hygiene.md");
For many files, use include_dir.

Important guardrail
Add an agentrail self-check:

agentrail instructions status
It should report:

Embedded instruction version: git commit abc1234
Repo CLAUDE.md block:        abc1234
Status: stale
Then agents can be told:

Before starting work, run agentrail instructions status.
If stale, run agentrail instructions apply.
My recommendation
Do not use cache for global instructions.

Use:

committed files in agentrail-rs + compile-time embedding + generated blocks in target repos
